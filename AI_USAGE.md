# AI Usage

The assignment allows AI assistance as long as it is documented openly. This
file covers what AI did, what was checked and how, and which AI output was
wrong and had to be fixed.

## 1. Tools used

| Tool | Model | Used for |
|------|-------|----------|
| Claude Code (VS Code extension) | Claude Opus 5.5 (`claude-opus-5-5`) | Inspecting the target sites, designing the architecture, writing the code, tests and documentation, running the pipeline and tests |

No other AI tools, paid APIs or online code generators were used. The
pipeline does not call any AI service at runtime.

## 2. How the AI was used (approach and prompt)

I gave Claude Code one long, structured prompt. It listed the assignment's
requirements phase by phase: study the documents, set up the project, HTTP
layer, Books scraper, Quotes scraper, cleaning, validation, deduplication,
consolidation, summary, logging, error handling, tests, README, AI_USAGE, and
a final audit. It also set ground rules: no invented data, no hard-coded page
counts, no placeholders, no bypassing site protections, and no claim that
tests pass unless they were actually run.

The agent worked in this order:

1. **Checked the live HTML first.** It downloaded sample pages with `curl`
   (Books listing pages 1 and 50, one detail page, Quotes pages 1 and 10) and
   checked every reference selector against the real markup before writing
   any parser.
2. **Wrote the code module by module** (HTTP client, base crawler, two
   scrapers, cleaning, validation, deduplication, output, pipeline, CLI).
3. **Ran a 2-page smoke test** against the live sites, then the full run.
4. **Wrote offline pytest tests** using HTML fixtures modelled on the real
   markup, and ran them.
5. **Tested a clean install** in a fresh Python 3.12 virtual environment
   using only `requirements.txt`.
6. **Audited** the generated CSV, JSON and log against the requirements.

## 3. Which parts are AI-generated

All of the code, tests, HTML fixtures and documentation in this repository
were generated by Claude Code. I did not write them by hand, and I am not
claiming to have done so. My part was defining the requirements, directing
the work, and reviewing and understanding the result (section 6).

## 4. AI output that was wrong or unsuitable, and how it was fixed

These were found during the session by checking against the real website or
by testing, not by assuming the code was correct:

1. **Truncated book titles.** The reference selector `h3 > a` returns the
   *visible* link text, which the site shortens (`"A Light in the ..."`). The
   scraper reads the link's `title` attribute instead, which holds the full
   title. A test covers this.
2. **Corrupted price symbol.** Books to Scrape sends `Content-Type: text/html`
   with no charset, so `response.text` decodes the UTF-8 page as Latin-1 and
   `£51.77` comes out as `Â£51.77`. The fix passes the raw bytes
   (`response.content`) to BeautifulSoup, which then honours the page's
   `<meta charset=UTF-8>`. `clean_price` also tolerates the corrupted form
   defensively.
3. **Price parser was too lenient.** The first version of the price regex
   accepted letters before the number, so `"abc5"` would have become `5.0`, a
   believable but invented price. It was tightened to allow only currency
   *symbols*, and a test now checks that `"abc5"` is rejected.
4. **`assert` in production code.** An early version of `clean_record` used
   `assert` to check column order. Asserts are skipped under `python -O`, so
   it was removed. A unit test checks column order instead.
5. **"...more" in descriptions.** Every book description on the site ends
   with a literal `...more` UI marker. It is now removed in
   `clean_description`, and the rest of the text is kept exactly as
   published.
6. **A wrong claim about the data, corrected after checking.** While the
   full run was still going, I (the AI) wrote here that "some *different*
   books on the site share a title" without having checked. The finished run
   showed only one shared title, *The Star-Touched Queen*. I then compared
   both live pages: same category and rating, a 92 %-identical blurb, but
   different UPCs and prices. I first called it "the same book listed
   twice", but that went too far; "two listings/editions of the same book"
   is what the evidence supports. The README now states exactly that, and
   notes that a UPC key would keep both.
7. **Test that only worked on some machines.** The first connection-error
   test pointed the client at a closed local port. On Windows that shows up
   as a `ConnectTimeout` instead of a `ConnectionError`, so the test failed.
   The client was fine. The test now injects each exception type directly,
   so it gives the same result on any OS.
8. **Rate limiter timing was slightly imprecise.** The throttle measured
   elapsed time with `time.monotonic()`, which on Windows only advances in
   ~15 ms steps. The rate-limit test failed once in about 18 full runs
   (measured 0.391 s against a required 0.4 s). The throttle now uses
   `time.perf_counter()` and loops until the full delay has passed. The test
   then passed 40 out of 40 repeated runs.

## 5. How functionality and correctness were verified

- **Unit and integration tests:** 126 pytest tests, all passing, run with
  Python 3.13.15 (project venv) and 3.12.10 (fresh venv). They cover cleaning,
  validation, deduplication (identical / case / whitespace / punctuation /
  distinct records), scraper parsing and pagination on fixture HTML, missing
  elements, malformed items, failed detail pages, failed listing pages,
  pagination loops, and one source crashing while the other still runs.
- **Live runs:** `python main.py` was run against both real sites, and the
  CSV, JSON and log were inspected (README "Results of the verified run").
- **Count check:** the summary confirms
  `raw = rejected + duplicates + final` overall and per source.
- **No invented data:** fields a source does not have (price/rating/category
  for quotes, author/tags for books) were confirmed empty in the CSV. Spot
  values were compared with the live pages (for example *A Light in the
  Attic*: £51.77, three stars, category Poetry).
